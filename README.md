# [اسم المنصة] — منصة إدارة المطاعم عبر QR

> **ملاحظة:** المنصة بدون اسم تجاري حتى يختار صاحب المشروع الاسم. يظهر في الواجهات
> `[اسم المنصة]` كعنصر نائب، والعنوان العام هو «منصة إدارة المطاعم عبر QR».

منصة SaaS متعددة المطاعم (Multi-Tenant) تحوّل تجربة الطلب داخل المطعم إلى تجربة
رقمية سريعة وسلسة. يمسح العميل رمز QR الخاص بطاولته، فيتصفح قائمة الطعام من
هاتفه ويرسل طلبه، دون تحميل تطبيق أو تسجيل دخول. يصل الطلب فورًا إلى المطبخ
ثم إلى فريق الخدمة، ويُتابَع حتى لحظة التقديم.

## كيف يعمل النظام

1. **المسح:** كل طاولة لها رمز QR فريد. يتعرف النظام تلقائيًا على المطعم ورقم الطاولة.
2. **التصفح والطلب:** يعرض النظام القائمة بتصنيفاتها وأسعارها وصورها، ويختار العميل
   أصنافه ويرسل الطلب.
3. **المطبخ:** يظهر الطلب فورًا في صفحة المطبخ، وعند الانتهاء يضغط الطاهي **«تم التجهيز»**.
4. **الخدمة:** ينتقل الطلب تلقائيًا إلى صفحة النادل، وبعد وصوله إلى الطاولة يضغط
   **«تم التقديم»** فيُغلق دورته.

دورة الطلب: **جديد ← جاهز ← تم التقديم**

## الأدوار

| الدور | الصلاحيات والمهام |
|---|---|
| **العميل** | تصفح القائمة، إنشاء الطلب وإرساله من الطاولة، دون تسجيل أو تحميل تطبيق. |
| **المطبخ** | استقبال الطلبات لحظيًا بترتيب الوصول، وتحديث حالتها إلى «تم التجهيز». |
| **النادل** | متابعة الطلبات الجاهزة بحسب الطاولة وتأكيد «تم التقديم». |
| **مدير المطعم** | إدارة القائمة والأصناف والأسعار والطاولات ورموز QR والعاملين، ومتابعة الطلبات والإحصائيات الخاصة بمطعمه. |
| **المشرف العام (Super Admin)** | إدارة جميع المطاعم المشتركة، وتفعيل الحسابات أو إيقافها، وعرض إحصائيات المنصة الشاملة. |

## أبرز المميزات

- **معمارية متعددة المطاعم:** مطاعم كثيرة على نظام واحد، مع عزل كامل لبيانات كل مطعم
  (كل جدول يحمل `restaurant_id`).
- **تحديثات لحظية:** انتقال الطلب بين العميل والمطبخ والنادل دون تأخير
  (في النسخة التجريبية: `storage` events + polling).
- **دورة طلب واضحة:** حالات محددة تقلل الأخطاء وتضمن المساءلة.
- **بدون تطبيق للعميل:** يعمل من المتصفح مباشرة على أي هاتف.
- **لوحة إحصائيات:** مؤشرات للطلبات والأداء على مستوى المطعم والمنصة.
- **سهولة الإعداد:** يبدأ المطعم بإضافة القائمة وطباعة رموز QR خلال دقائق.

## التشغيل

لا توجد اعتماديات خارجية، فلا حاجة لـ `npm install`.

```bash
node server.js
```

ثم افتح في المتصفح:

- http://localhost:3000 — الصفحة الرئيسية
- http://localhost:3000/menu.html?restaurant=r1&table=5 — قائمة العميل لطاولة 5
- http://localhost:3000/kitchen.html — المطبخ
- http://localhost:3000/waiter.html — النادل
- http://localhost:3000/manager.html — مدير المطعم
- http://localhost:3000/admin.html — المشرف العام

لتغيير المنفذ:

```bash
PORT=8080 node server.js
```

## البيانات التجريبية

النسخة الحالية **تجريبية محلية**:

- مطعمان تجريبيان، ولكل مطعم طاولات وقائمة كاملة (مشويات، بيتزا، برجر، مشروبات، حلويات).
- الطلبات والقائمة المعدّلة تُحفظ في `localStorage` في المتصفح
  (مفاتيح تبدأ بـ `qr-saas-`)، وتُحدَّث الصفحات المفتوحة لحظيًا عبر
  `storage` events مع polling احتياطي.
- الخادم يوفّر أيضًا API بسيطًا في الذاكرة (`/api/orders`) للتجربة،
  لكن واجهات العرض تعتمد على `localStorage` لتعمل حتى بدون خادم.

لإعادة ضبط البيانات التجريبية: امسح بيانات الموقع من المتصفح أو احذف
مفاتيح `qr-saas-*` من `localStorage`.

## إعداد Supabase (للنسخة الإنتاجية)

1. أنشئ مشروعًا في [Supabase](https://supabase.com) واحصل على
   `SUPABASE_URL` و `SUPABASE_ANON_KEY` و `SUPABASE_SERVICE_ROLE_KEY`.
2. انسخ ملف الإعدادات واملأه:

   ```bash
   cp .env.example .env
   ```

3. في لوحة Supabase افتح **SQL Editor** ونفّذ محتوى `supabase/schema.sql`.
   ينشئ الملف الجداول: `restaurants`, `tables`, `menu_categories`,
   `menu_items`, `orders`, `order_items`, `staff` — وكلها تحمل
   `restaurant_id` لعزل بيانات كل مطعم.
4. فعّل Row Level Security (RLS) كما هو موضّح في التعليقات داخل
   `schema.sql`، واربط كل مستخدم بمطعمه عبر `restaurant_id`.
5. لا تنشر ملف `.env` أبدًا (موجود في `.gitignore`).

## التقنيات

- **الواجهة والخادم:** HTML + Node.js (بدون اعتماديات).
- **قاعدة البيانات:** Supabase (PostgreSQL).
- **الإعدادات:** متغيرات حساسة عبر ملف `.env`.
- **التصميم:** عربي RTL، متجاوب مع الهواتف، لوحة ألوان دافئة للمطاعم.

## خارطة الطريق المقترحة

- ربط واجهات العرض بـ Supabase Realtime بدل `localStorage`.
- تسجيل دخول للمدير والمشرف العام وربط `restaurant_id` بالجلسة.
- توليد رموز QR داخل النظام وطباعتها.
- مدفوعات إلكترونية وتقارير مبيعات متقدمة.
